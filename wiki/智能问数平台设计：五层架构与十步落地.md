# 智能问数平台设计：五层架构与十步落地

> 一句话要点：把智能问数（NL2SQL）从"能转 SQL"升级为生产级平台，靠的是五层架构（数据库/数据/引擎/服务/表现）与"先治理再智能、语义层先行、分层模型 + 三道校验、权限贯穿全链路"的工程纪律。

## 关键要点

- 重新定义目标：智能问数不是"转 SQL"，而是"让不懂 SQL 的业务人员能**安全、准确**地查到数据"——准确与安全是生产环境的两个硬门槛。
- 场景分四档难度：L1 单表（⭐，目标 99% 准确率）/ L2 多表关联（⭐⭐⭐，85%）/ L3 复杂指标（⭐⭐⭐⭐，靠预定义指标兜底）/ L4 自由探索（⭐⭐⭐⭐⭐，现阶段仅辅助）。
- 核心论断：**NL2SQL 准确率 70% 靠数据层、30% 靠模型层**——字段有注释命名规范的库轻松 95%+，字段叫 c1/c2 的库即使用 GPT-4o 也救不回（<50%）。原则："先治理，再智能"。
- 五层架构（自底向上）：① 数据库层（MySQL/PG/ClickHouse…）→ ② 数据层（指标库/语义映射/Schema）→ ③ NL2SQL 引擎层（Schema Linking / SQL 生成）→ ④ 服务层（意图路由/权限/缓存）→ ⑤ 表现层（问答/图表/导出）。
- 语义层是数据层的关键：在物理表与用户间做翻译（"销售额"→SUM(amount) WHERE status IN …），屏蔽物理结构、统一口径、封装复杂逻辑。落地推荐自建轻量 Schema 注册表，而非硬上 dbt。
- NL2SQL 引擎核心链路：用户问题 → 意图识别（小模型分类）→ Schema Linking（粗筛→上下文压缩→Prompt 构建）→ SQL 生成（按复杂度路由小/中/大模型）→ 三道校验（语法检查 / 安全策略 / 只读副本隔离）→ Self-Correction（最多重试 3 次）→ 执行。
- 服务层三件套：多轮对话（对话状态机）、结果缓存（以标准化查询为 key，TTL 30 分钟，命中率 60%+）、权限控制（RBAC + 行级权限自动注入 WHERE + Schema 只暴露有权范围 + 结果限行脱敏，贯穿全链路而非最后拦截）。
- 结果呈现三层：数据表格 + 自动选图 + 一句话解读；处理不了的不硬编，反问澄清口径。
- 风险预案四条：准确率、查询太慢、权限绕过、用户期望过高。
- 用户反馈即训练样本：把（问题, 正确SQL, 用户修正SQL）沉淀为 Few-shot 样本，反哺语义层与模型。

## 详细笔记

文章最可迁移的方法论是"**语义层先行 + 分层模型做省 + 权限贯穿**"。语义层把"业务术语→物理 SQL 片段"的映射前置固化；分层模型（小/中/大按复杂度路由）兼顾成本与成功率；权限不在最后拦截而在 Schema Linking 阶段就收紧，是"企业敢不敢用"的关键。这套思路与 AI Coding 工作流里"spec 先行、ticket 拆分到单 context、review 贯穿"有结构上的同构性（推论）。
