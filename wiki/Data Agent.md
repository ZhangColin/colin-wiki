# Data Agent

> 一句话定义：建立在企业数据平台、指标体系、语义模型和权限体系之上的专业 Agent——理解用户的数据问题，识别业务对象、指标和分析维度，选择正确数据源，调用查询与分析工具，把结果转化为业务人员能理解的结论与行动；是「企业数据从'被治理'走向'被智能消费'」的形态。

## 核心观点

### Data Agent ≠ NL2SQL（双源一致否定）

- [[白墨]]（[[企业 Agent 落地十二大工程框架]]）：「生成查询语句只是其中一个环节」，成熟 Data Agent 还需指标识别、数据源路由、业务语义理解、查询校验、权限控制、多轮分析、结果验证、异常发现、业务解释和依据展示。
- [[智能问数平台]]：「智能问数不是转 SQL，而是让不懂 SQL 的业务人员能**安全、准确**地查到数据」；「70% 靠数据层、30% 靠模型层」。

### 能力三层次（白墨）

**查询型 → 分析型 → 行动型**：查询数据 → 分析数据 → 解释数据 → 提出建议 → 触发行动。

- L1 查询型：自然语言 → 正确查询 → 表格/数值/基础图表。
- L2 分析型：围绕问题做趋势比较、指标拆解、维度下钻、异常分析（「本季度华东区销售额为什么下降」→ 按产品/城市/渠道/客户类型下钻）。
- L3 行动型：洞察转业务行动（发现异常 → 定位 → 分析原因 → 生成跟进建议 → 创建销售任务 → 分派 → 跟踪）。
- 「越往上走，离业务行动越近，对数据和治理的要求也越高」；「Data Agent 的成熟不是 SQL 越复杂越好，而是能否在正确权限、可信数据和统一业务口径下稳定回答，并把可靠洞察转化为业务结果」。

### 事实-推测-行动信任链（白墨，安全设计核心）

输出必须区分五个信任层级，逐级加码：

| 层级 | 要求 |
| --- | --- |
| 数据事实 | 直接展示 |
| 统计发现 | 说明计算方法 |
| 业务推测 | 标记为待验证假设 |
| 因果结论 | 需更强证据 |
| 行动建议 | 结合风险与业务责任决定是否人工复核 |

「越靠近行动，越需要证据和人工复核」；高风险分析「不应把相关性包装成因果关系，也不应在数据不足时给出确定性结论」。

### 可靠工作的底座（前置工程）

- **Data Engineering**：「Data Engineering 让数据准备好，Data Agent 让数据用起来」——数据源地图与权威来源判断、主数据管理（同一客户多编号的实体对齐）、可信数据管道；数据不准时「模型只会把不准确的数据组织成一个更加完整、更有说服力的错误答案」。
- **语义层与指标口径**：字段的**业务含义**（某表字段是什么意思）、指标如何计算、按哪些维度拆分、适用什么时间口径、从哪个数据源取——「客户数」可能指注册/下单/付费/活跃（白墨）；语义层是准确率主要来源与权限注入挂载点（[[智能问数平台]]）。
- **权限贯穿**：表级/行级/列级/字段级权限，零信任拦截——「过滤在信息进入模型上下文之前完成，无权限数据不进推理链路」（白墨）；「不在最后拦截，而在 Schema Linking 阶段就收紧」（[[智能问数平台]]）。

### 平台形态：五层架构（[[智能问数平台]]）

数据库层 → 数据层（指标库/语义映射）→ NL2SQL 引擎层（Schema Linking / SQL 生成）→ 服务层（意图路由/权限/缓存）→ 表现层；场景分四档难度（L1 单表 99% / L2 多表 85% / L3 复杂指标靠预定义兜底 / L4 自由探索辅助）。「先治理，再智能」。

## 与 AI Coding 工程方法论的跨领域同构（推论）

「语义层先行 + 分层模型路由 + 贯穿式校验/权限」（Data Agent）与 [[mattpocock skills]] 的「spec 先行 + ticket 拆到单 smart-zone + 贯穿式 code review」同构——都是「前置规范化 + 分级处理 + 全链路质量门」。与 [[Harness Engineering]] 的关系：Data Agent 是十二工程协同形成的专业 Agent（白墨），并非第十三项独立工程；[[Agent 测评 Eval]] 的「查询成功≠底层数据完整、计算正确≠业务解释成立」分层评估要求同样适用于此。

## ⚠️ 矛盾 / 未解问题

- 「70% 靠数据层、30% 靠模型层」与 L1/L2 准确率目标值为作者经验/设计值，非实测。
- 两源对 Data Agent 的定位一致（专业 Agent 非独立工程），但视角互补：白墨给能力分层与信任链（企业 Agent 工程视角），[[智能问数平台]] 给平台架构与落地步骤（系统建设视角）。
