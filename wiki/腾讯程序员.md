# 腾讯程序员

> 一句话定义：微信公众号「腾讯程序员 / 腾讯技术工程」；本 wiki 收录其三篇——atreusliu 的 [[Harness Engineering 团队落地规范]]（harness 怎么建）、martinskxu（TEG 云架构平台部网关测试团队）的 [[腾讯 Agent 与 Skill 测评方案]]（harness 怎么验）、fitchzheng & leoshli（TAB A/B 实验平台团队）的 [[TAB 大仓 Harness 工程化实战]]（harness 在大仓怎么撞墙补稳），代表大厂团队级 AI Coding 治理视角。

## 概述

在本 wiki 语境下，「腾讯程序员」的价值是提供了 **团队级（而非个人级）的 Harness 落地样本**：把 OpenAI 的 Harness Engineering 理念（6 大支柱）落到具体工具链（CodeBuddy 插件、Knot 平台、team-harness 仓库、harness-audit 审计 Skill），并给出 3 阶段实施路线图与 SOP/反模式/红线清单；随后又从测试团队视角给出 [[Agent 测评 Eval]] 的完整工程化方案；再以 TAB 大仓实战补上最细颗粒度的撞墙复盘——三篇构成"建 + 验 + 稳"三部曲。

## 关键属性 / 事实

- **品牌**：公众号「腾讯程序员 / 腾讯技术工程」；本文署名 atreusliu。
- **生态**：腾讯 CodeBuddy（IDE 插件 + CLI）+ Knot 平台（知识库/MCP/Rules/Skills/智能体管理）+ 司内 CLI（Claude Code Internal / Gemini CLI Internal / Codex CLI Internal）。
- **核心主张**："让各类工具适配规范，而不是靠个人去适配各类工具"；"流水的工具，铁打的规范"。
- **方法论贡献**：harness-audit Skill——"Skill 就是规范的可执行版本"（7 维度打分，把规范固化为可执行的合规性审计）。
