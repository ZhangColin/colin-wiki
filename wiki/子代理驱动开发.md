# 子代理驱动开发

> 一句话定义：[[Superpowers]] 的核心执行模式——"Fresh subagent per task + two-stage review"，把大任务拆成独立子任务，每个子任务由一个干净上下文的子代理实现，再经独立审查；上下文隔离防污染、独立审查防护短。

## 核心观点

### 为什么需要子代理

- **上下文隔离**：主代理（controller）若边想边写，working state 会被早期决策污染；每个 task 派给 fresh subagent（干净 context）实现，避免漂移。
- **防自审护短**：main agent 写完代码会护短（"我写的，挺好"）；拆给独立 sub-agents 审查更客观。这是"作者和审查者绝不在同一上下文里互评"的根本理由。
- [[Jesse Vincent]] 原则：执行者应被假设为 "an enthusiastic junior engineer with poor taste, no judgement, no project context"，故必须隔离 + 审查。

### 两阶段审查（v5.x）→ 单 reviewer（v6.0）

- **v5.x**：每个 task 后跑两轮独立 review——第一轮规格符合性（查"缺失"与"多余"），第二轮代码质量（风格/边界/性能）。必须按序。
- **v6.0 结构性变更**：合并为单一 `task-reviewer`，"reads the task's diff once and returns two verdicts"（少读一遍 diff、少起一个 subagent）。详见 [[Superpowers 6.0 reviewer 只读重写]]。
- **v6.0 reviewer 三特质**：① 只读（曾发生 reviewer 跑 `git checkout` 致孤儿提交）；② 怀疑论者（"Do Not Trust the Report"，implementer 自述不能降低发现严重性）；③ controller 禁止辅导 reviewer（禁止告诉 reviewer 不要标记什么）。

### Model 纪律

- **v5.x 痛点**：派 subagent 不指定 model → 静默继承 session 顶配（一次运行 26 个 reviewer 全跑顶配）。
- **v6.0 修复**：两模板开头强制声明 model——"an omitted model silently inherits the session's most expensive one"。
- **反直觉规律**：便宜模型多步任务要跑 2-3 倍轮次反更贵，故按复杂度匹配档位（机械实现用快速/廉价模型、集成判断用标准模型、架构/审查用最强模型），"不要用旗舰级模型去定义 DTO"。

### Progress Ledger 对抗 compaction 失忆

git-ignored 的 `progress.md` 每完成一 task 追加一行；compaction 后 controller 读 ledger + git log 恢复进度；"trust the ledger and git log over your own recollection"。官方称重派整套已完成 task 是"观测到的最昂贵失败模式"。

### 上下文经济学（v6.0）

5.x 把 task 文本和 diff 粘进 dispatch prompt，永久占用 controller context；6.0 用三脚本（`task-brief`/`review-package`/`sdd-workspace`），subagent 读文件而非接收粘贴，单独省约 10% token 和时间。

## ⚠️ 矛盾 / 未解问题

- **两阶段审查描述在 v6.0 后已过时**：[[Superpowers 7阶段交付SKU库存扣减]] 与 [[Superpowers 7步闭环工作流深度指南]]（v5.x 时代）详述"两轮独立审查"，v6.0 已合并。读旧页时注意版本。
- writing-plans 结构变更：v6.0 每个 task 必须带 Interfaces block（Consumes/Produces 精确签名），因 implementer 只看自己 brief。
