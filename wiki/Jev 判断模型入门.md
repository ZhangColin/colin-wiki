# Jev 判断模型入门

> 一句话要点：TypeSafe 的 [[Jev]] 是「**聪明的 if 语句**」——不聊天、只做判断的 system one 模型，返回结构化数据而非文本；快与便宜源于**无需逐 token 生成、答案概率并行计算**。「模型变窄，反而更好用。」

## 关键要点

- **定位**：写不进 if-else 的判断（例：「顾客留言是否不满」——关键词抓不住「我已经联系你们三次了，还在等」这类无关键词的不满）。官方定义：system one 模型，做**快速、结构化、软件可直接使用**的判断。名字双出典：system one（卡尼曼《思考，快与慢》的快直觉）+ Jevons 悖论（**判断一旦便宜到可忽略，就会被塞进以前算不过账的场景**——TypeSafe 对 AI 的预期）。
- **与聊天模型的本质差别**：GPT/Claude 也能判断，但它们还要写回复/解释/生成代码；Jev 只做判断这一件事，不生成回复不解释答案 → 概率可并行计算。同一任务对照：GPT-5.6 Terra **8.6 秒 / 约 1.4 美分** vs Jev **114 毫秒 / 不到百分之一美分（约 1/170）**。
- **定价**：输入 $42/十亿 token（$0.042/百万），**输出不计费**；尺度换算：每条留言+问题约 500 token，**1 美元查 4.7 万条**——「把每一条进来的留言都过一遍，花在判断上的钱不多」。
- **输入结构**：state（交给模型看的材料：文本/JSON/数组）+ 问题组，三类问题——
  - **Noul**（是非）：返回「是」的概率 0–1；低值≠拿不准，是确定「否」；0.5 附近才是无偏向；
  - **choice**（选项）：从调用方定义的列表里必选一个（「其他」不能省），返回选中项+全部选项概率；
  - **score**（刻度）：各级写含义（比「1-10 分」给模型更明确参照），得分=各级概率加权平均，可落在两级之间（1.02=表达了不满但未到强烈愤怒）。
  - 多问题共用 state **单次调用并行评估**（「独立」的明确含义：一个问题读不到另一个的答案）——省 token 也省网络往返。
- **置信度**：choice/score 额外返回 confidence（按概率分布算），用于决定直接采纳还是留人复核；**Noul 无单独字段，看概率偏向强度**。「置信度不是准确率的保证」——阈值没有通用答案，拿自己样本试。
- **实操路径**：Playground 先跑（92% true 演示）→ TypeScript SDK（`@typesafe-ai/sdk`），`client.system1(state, questions)`；复核阈值演示 0.8（超阈值标给客服），实际阈值要拿代表性样本跑过再定。
- **选型判据三条全占才用**：有一个判断要做 / 答案描述得出（选项列得出、各级判据写得下）/ 速度或重复调用对业务重要。**不该用**：生成类任务；**不该用任何模型**：代码能精确算的（算数、计数、日期、购物车满三件）。

## 与已有内容的关联

- **Eval 关联（最实质）**：Jev 是 [[Agent 测评 Eval]] 中 **Rubric 评分器（LLM-as-Judge）**的专门化基础设施候选——毫秒级/低成本让「判断」从挑重点场景变为可高频内嵌（Jevons 悖论的工程兑现）；但「置信度≠准确率」，作为 judge 仍需人工校准（Eval 页的一致率门槛），两类问题互补不互替。
- **与「变窄」主题同族**：「判断单独抽出、其余交还代码」与 [[Skills 设计方法论]]「Skill 是注意力管理」同一方向——都在把 LLM 从万能对话框拆成窄而快的组件（推论）。
