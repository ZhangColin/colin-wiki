# 智能问数平台

> 一句话定义：让不懂 SQL 的业务人员能用自然语言**安全、准确**地查到数据的平台（NL2SQL/Text-to-SQL 的生产级形态）；核心命题是把"能转 SQL"升级为"五层架构 + 语义层先行 + 权限贯穿全链路"。

## 核心观点

### 重新定义目标

智能问数不是"转 SQL"，而是"让不懂 SQL 的业务人员能**安全、准确**地查到数据"——准确与安全是生产环境的两个硬门槛。

### 核心论断：70% 靠数据层、30% 靠模型层

字段有注释命名规范的库轻松 95%+ 准确率，字段叫 c1/c2 的库即使用 GPT-4o 也救不回（<50%）。原则：**"先治理，再智能"**。（作者经验性论断，未给实验依据）

### 五层架构（自底向上）

① 数据库层（MySQL/PG/ClickHouse…）→ ② 数据层（指标库/语义映射/Schema）→ ③ NL2SQL 引擎层（Schema Linking / SQL 生成）→ ④ 服务层（意图路由/权限/缓存）→ ⑤ 表现层（问答/图表/导出）。

### 语义层（最可迁移的方法论）

在物理表与用户间做翻译（"销售额"→`SUM(amount) WHERE status IN …`），屏蔽物理结构、统一口径、封装复杂逻辑。既是准确率的主要来源，也是权限注入的挂载点。落地推荐自建轻量 Schema 注册表，而非硬上 dbt。

### 权限贯穿全链路

RBAC + 行级权限自动注入 WHERE + Schema 只暴露有权范围 + 结果限行脱敏——不在最后拦截，而在 Schema Linking 阶段就收紧。是"企业敢不敢用"的关键。

### 场景分四档难度

L1 单表（目标 99%）/ L2 多表关联（85%）/ L3 复杂指标（靠预定义指标兜底）/ L4 自由探索（现阶段仅辅助）。

## 与 AI Coding 工程方法论的跨领域同构（推论）

"语义层先行 + 分层模型路由 + 贯穿式校验/权限"与 [[mattpocock skills]] 的"spec 先行 + ticket 拆到单 smart-zone + 贯穿式 code review"在工程方法论上同构——都是"前置规范化 + 分级处理 + 全链路质量门"。若后续出现第 2 篇相关源，可沉淀 synthesis《AI 工程化方法论的跨领域同构》。

## ⚠️ 矛盾 / 未解问题

- "70% 靠数据层、30% 靠模型层"为作者经验论断；L1/L2 目标准确率（99%/85%）为设计目标值，非实测数据。
