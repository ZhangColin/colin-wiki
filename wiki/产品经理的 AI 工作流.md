# 产品经理的 AI 工作流

> 一句话要点：[[SinKris]]（Kris产品成长之路）公开其每天在用的 8 个产品经理 AI 工作流（工具 + Prompt + SOP，可直接复制），核心主张「**工作流 = 标准化流程 + AI 自动化 + 可复用模板**」——AI 处理 80% 基础工作，人专注 20% 高价值工作。

## 关键要点

- **开场实证**：需求分析 2 天→2 小时（10 倍）、竞品分析 3 天→3 小时（8 倍）、PRD 2 天→2 小时（8 倍）——「不是找到了什么神奇工具，而是建立了 AI 工作流」（均为自述口径）。
- **8 个工作流**（每个含工具推荐 + Prompt 模板 + SOP + 真实案例）：
  1. **需求分析**（30 分钟）：访谈记录提取结构化信息（画像/痛点强度 1-5 分/明确 vs 隐含需求/关键引语）→ KANO 模型五类分类（基本/期望/兴奋/无差异/反向 + 成本估计 + P0/P1/P2）→ 结合业务目标与资源约束智能排序（Top 3 + 风险提示）。
  2. **竞品分析**（3 小时）：快速调研（公开资料 + 来源链接）→ 截图深度拆解（信息架构/交互设计/产品策略/可借鉴之处）→ 结构化报告（概述/优势/劣势/策略建议，「数据要有来源、结论要有依据、建议要可执行」）。
  3. **PRD 撰写**（2 小时）：需求结构化（背景/目标用户/功能说明含「不做的功能」/成功指标 + **「帮我补充我没想到的部分，并指出逻辑漏洞」**）→ 生成用例（正常/异常/边界 + 性能要求 + 开发关注点）→ 评审材料（PPT 大纲 + 预测产品总监/开发 leader/设计师各问什么 Top 10）。
  4. **数据分析**（2 小时）：CSV 上传快速诊断（趋势/异常点/3-5 个假设 + 验证方法）→ 用户分群分析（找问题用户群共同特征）→ 策略推荐（短期应急/中期优化/长期改进 + 验证指标，策略矩阵输出）。
  5. **项目管理**（每周 1 小时）：风险识别（时间/资源/协作/技术四类 + 等级 + 预案 + 预警信号）→ 周报生成（红黄绿风险标注、需老板决策事项单列）→ 复盘报告（目标 vs 实际/做得好与不好 Top 3/关键决策回顾/方法论沉淀）。
  6. **跨部门协作**（35 分钟）：需求翻译成开发语言（输入/处理逻辑/输出/接口要求/边界条件）→ 方案包装成老板语言（业务价值/资源需求/ROI/明确决策建议）。
  7. **个人成长**（每周 20 分钟 + 年度 1 小时）：经验萃取（经验卡片：场景/方法/效果/标签）→ 述职材料（成果 Top 5 量化 + 能力证明 + 4 段式结构 + 预测评委问题）→ 知识体系构建（三级分类框架 + 知识关联 + 学习路径）。
  8. **创意激发**（2 小时）：头脑风暴 10 方案（要求多样化、常规 + 创新）→ 四维打分（用户价值 0.4 + 商业价值 0.3 + 可行性 0.2 + 创新性 0.1）→ MVP 细化（范围/验证指标/实施路径/风险预判）。
- **建立工作流的 3 原则**：①标准化——重复性工作变固定流程（输入→AI 处理→输出→人工优化）；②自动化——80/20 分工，AI 做信息搜集/内容生成/数据分析/格式转换，人做判断方向/决策/创意/人际沟通；③可复用——一次性 Prompt 变成模板库（按场景分类的 md 文档，**点名 Notion/飞书/Obsidian 均可作载体**）。
- **核心公式**：「你的价值 = AI 处理的基础工作量 × 你的判断质量」；「AI 工作流的本质：不是让你做得更快，而是让你做得更对」；「AI 不会替代产品经理，但会用 AI 工作流的产品经理会替代不会用的」。
- 工具清单：Claude/ChatGPT（长文本/访谈）、Perplexity（调研）、Notion AI/飞书 AI（文档内）、飞书妙记/Otter（会议纪要）、Code Interpreter（图表）、自定义 GPTs（固化业务逻辑）、Obsidian + AI 插件（知识管理）。

## ⚠️ 矛盾 / 待澄清

- 效率数字（2 天→2 小时等）为作者自述，无对照实验；「10 倍」与 OpenAI Harness 文的「10 倍」数字巧合，口径完全不同（个人工作流 vs 团队全 Agent 开发）。
- Prompt 模板为通用模板，非深度定制（对比 [[mattpocock skills]] 的触发机制与上下文工程，属于轻量级应用）。
