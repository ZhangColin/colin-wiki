## 场景：需求来了，能不能三个 AI 一起上？

艳姐提了个新需求：「预算页我要能一眼看到哪些分类超支了——超支的给我标红，最好一进页面就有个提示。」

这个需求拆开看，天然是两块：

- 后端： 给"某分类本月支出是否超预算"算出来，加进接口；
- 前端： 预算页把超支分类标红、加提示。

两块 **各自能独立验证** （后端跑测试、前端看页面），互相只通过"接口长啥样"这个约定耦合。这种活，就是 `dispatching-parallel-agents` （并行派发）的菜： **拆成互不依赖的小任务，一次派给多个 AI 并行干。**

老王搓搓手：「这不就是流水线开多台机器？」

「对，但机器开多之前，得先把 **活拆对** 。」

## 技能是什么：并行派发的核心是"拆"

`dispatching-parallel-agents` 讲的不只是"怎么让 AI 并行"，更是 **什么活才配并行** 。它的核心动作是拆：

1. 拆到任务之间不互相依赖——A 改 A 的文件，B 改 B 的文件，谁也不等谁；
2. 拆到每个任务都能独立验证——A 跑后端测试，B 看前端页面；
3. 拆之前先定接口契约——前端要调什么接口、返回什么 JSON，先钉死；
4. 每个子代理只领一个任务，任务边界写清楚，不许越界发挥。

**拆不好，并行就是灾难** ：两个 AI 改同一个文件，改出来的是一堆冲突。拆得好，每个 AI 闷头干自己的，收工时拼起来就是完整功能。

## 怎么用：把"超支提醒"拆成两路

### 第一步：定接口契约

并行之前，先定"前后端握手"的接口。超支判断放在后端，前端只负责渲染。约定：

```
GET /api/budgets?month=2026-08
→ [{ "categoryId": 1, "month": "2026-08", "limitAmount": 2000.00 }]
```

再约定一个前端自己算还是后端算？ **为了前后端各管各的，超支判定在后端接口里就带上** ：每个预算项附一个"本月已花 `spent` "。前端拿着 `spent` 跟 `limitAmount` 比，标红就完了。

契约钉死，两路开工。

### 第二步：派发——给每个 AI 写清边界

给子代理 A（后端）的任务：

> 任务：给预算接口加"本月已花"字段。  
> 文件： `ReportController` 、 `LedgerAppService` 、对应测试。  
> 验收： `mvn test` 全绿； `GET /api/budgets?month=2026-08` 返回的每个预算项带 `spent` 字段。  
> 边界：只改后端，不碰前端任何文件。

给子代理 B（前端）的任务：

> 任务：预算页把超支分类标红并加提示。  
> 文件： `src/views/Budgets.vue` 、相关样式。  
> 验收： `npm run dev` 下，预算表里 `spent > limitAmount` 的行标红，页面顶部弹出"X 分类超支"提示。  
> 边界：只改前端，不碰后端。

注意每张任务单里都有 **文件边界** 和 **验收标准** 。这就是防止"并行变踩踏"的护栏。

### 第三步：并行执行 + 逐个收

两个子代理各开各的（可以配合上一篇的 worktree，也可以各领各的文件），我作为"调度员"在主会话等结果。

收工验收，一个都不能少：

- 后端 A 交回： `mvn test` 全绿，接口带 `spent` ；
- 前端 B 交回：预算页标红生效，截图或描述可见；
- 拼起来：前端调的字段名跟后端返回的字段名对得上（契约没破）。

### 第四步：合并 + 主干再验

两边都过了，走上一篇的收尾：各自提交 → 合回主干 → **主干跑一遍完整测试** 。

```
cd 202608-superpowers
git merge agent-a-budget-backend
git merge agent-b-budget-frontend
"$MAVEN_HOME/bin/mvn" test   # 主干再验一遍
```

## 什么时候不该并行

`dispatching-parallel-agents` 也明说： **不是所有活都适合并行** 。

- 两个任务改同一个文件 → 不该并行，会互相踩；
- 任务 B 依赖任务 A 的产出 → 不该并行，得排队；
- 任务太小（10 分钟能干完） → 派发本身的沟通成本比干活还高，不如自己干；
- 验收标准说不清 → 先写清验收再谈并行。

判断标准就一条： **拆开之后，每个任务能不能"孤零零地完成并验证"？** 能，才并行。

## 注意事项

1. 契约先钉死，再谈并行。 前后端约好的接口字段，是并行不撞车的命根子。改契约要两边同步，别各改各的。
2. 每个子代理的任务单要含"文件边界 + 验收"。 没有边界，AI 就会越界发挥；没有验收，交回来的活没法判断好坏。
3. 收工逐个验，不打包验收。 每个子代理的产出单独验，谁没过打回去谁重做，不拖累另一边。
4. 合并后主干再跑一遍测试。 两个分支各自绿，合到一起未必绿。主干测绿才收工。

## 本文小结

`dispatching-parallel-agents` 教我们： **并行之前先拆对** ——任务互不依赖、能独立验证、契约钉死、边界写清。拆对了，一个活变两路，一次派俩 AI。
