## 前言

写这篇专题之前，我先回想了一下自己学新东西的经历。

每次都是同一个剧本。看到一篇好教程，收藏。读的时候觉得全会了，划重点，点头。三天后用到，脑子里只剩一个模糊的印象，细节全忘。再翻收藏夹，又从头读一遍。

问题出在哪？出在学习方式上。教程是「一次性的」，它假设你读一遍就会了。可学习从来不是一次性的事，它需要反复、需要练习、需要记录、需要有人知道你现在学到哪了。

你可能会说，这不就是问 AI 吗？不懂就问。但普通问答式学习也是「一次性的」：你问一句，它答一句，聊完就散。下次你再问，它不记得上次教到哪。你的学习进度，只存在于你的脑子里，还经常忘。

`/teach` 解决的就是这个问题。它把「学习」从聊天变成工程：在当前目录里建起一套有状态的教学工作区，你的学习进度全部落盘，跨会话延续。

前两篇专题（loop-me、batch-grill-me）我都先说了，它们是 in-progress 草稿。这一篇不一样，teach 是正式技能，在官方 README 和 ask-matt 路由器里都挂着号，有独立的文档页。它是 Matt 的 productivity 桶里少有的几个正式成员之一。

## teach 是什么

一句话：跨会话教用户一个新技能或概念，把当前目录变成有状态的教学工作区。

关键在「跨会话」和「有状态」两个词。

普通的问答式学习是这样的：你问一句，AI 答一句，聊完就散。下次你再问，它不记得上次教到哪。你的学习进度，只存在于你的脑子里，还经常忘。

teach 不是这样。你输入 `/teach` ，告诉它你想学什么，它就在当前目录里建起一套教学工作区。你的学习状态被写进文件：为什么学（MISSION）、学了什么（learning-records）、有什么资源（RESOURCES）、你偏好怎么学（NOTES）。下次会话打开同一个目录，它读一遍这些文件，接着上次继续教。

学习从「聊天」变成了「工程」。状态落盘，进度可见，跨会话延续。

这跟 loop-me 的「有状态工作区」是同一个思路。loop-me 把工作流写进 workflows/\*.md，teach 把学习状态写进 MISSION.md 和 learning-records。Matt 的 skill 里，凡是要跨会话持续的事，都靠目录里的文件撑状态。

## 教学工作区长什么样

teach 规定的工作区有七个部件，逐个说。每个都配一个例子，你就明白它是怎么工作的了。

MISSION.md，使命文件。记录用户为什么对这个主题感兴趣，一切教学都锚定在这上面。举个例子，你想学 Spring Boot，MISSION.md 里写的就是：为什么学（项目里要用）、现在什么水平、学完要能做什么。这几行字决定每一课讲什么，没有一课是随手写的。

RESOURCES.md，资源清单。高质量、高信任的资源列表，用来给教学提供上下文。teach 有一条很硬的规矩：在 RESOURCES.md 填好之前，教学的重点是先找高质量资源，绝不信任 AI 自己的参数化知识。你以为 AI 什么都懂，但它讲错的时候，没有资源兜底，你根本发现不了。

NOTES.md，草稿本。记用户的偏好和工作笔记。比如你习惯中文还是英文、喜欢短课还是长课、示例能不能用你熟悉的语言、要不要每课配小测验。这些偏好，决定了每一课长什么样。AI 每次设计课程前都会翻它。

lessons/，课程目录。一课是一个自包含的教学单元，教一件与使命紧密相关的小事。官方设定课程是 HTML 文件，要渲染得漂亮、方便本地打开。但格式可以改，后面边界那一节会细说。

reference/，参考文档目录。压缩过的学习成果：速查表、算法、术语表。学编程，这里是语法速查；学瑜伽，这里是体式速查。teach 的设定是：课程很少被重访，参考文档会一直被重访，所以参考文档要做成快速查阅的压缩精华。

learning-records/，学习记录目录。捕捉非显然的教训和关键洞见，编号 0001 递增。teach 原话：学习记录在软件里类似架构决策记录（ADR）。它有两个用途，一是记录教训，二是用来计算下一步教什么。每份记录都记着你上次学到哪、卡在哪、下一步学什么，学得越多，记录越多，AI 对你越了解。

assets/，可复用组件目录。样式表、测验组件、模拟器，第二节课能复用的东西都放这。共享样式表是每个工作区第一个挣到的组件，让所有课程看起来像一个整体，而不是一堆散件。

七样东西，职责分明。使命定方向，资源供知识，记录算进度，课程给产出，参考做速查，笔记存偏好，组件保复用。

## 知识、技能、智慧

teach 的哲学是：深度学习需要三样东西。

Knowledge，知识，从高质量高信任的资源里获得。学开源框架，知识来源就是它的官方文档和源码仓库，写进课程前最好核对过一手来源，确保不写错。

Skills，技能，通过高度相关的交互式课程习得，基于知识设计。知识是「知道」，技能是「会做」。光看不练不是技能，所以课程一定要带练习，练习要有反馈，最好即时反馈。

Wisdom，智慧，来自和其他学习者、实践者的真实互动。这是 AI 教不了的部分。所以 teach 的默认姿态是：你问的问题如果涉及智慧，它先尝试回答，但最终会把你引向社区。论坛、线下班、同好小组，去真实世界里检验你的技能。

知识型主题和技能型主题要分开对待。学理论物理，知识为主。学瑜伽，技能为主。teach 会按主题调配方，不是一套模板打天下。

## 流利 vs 存储

这一节是整篇最值得带走的，它解释了「学完就忘」到底是怎么回事。

teach 把学习分成两种强度。

流利强度，当下的提取能力。你刚看完一篇教程，觉得全会了，这就是流利强度，很高。它给你一种虚幻的掌握感，但其实只是工作记忆里还热乎。

存储强度，长期的保持能力。过两周你还记得多少，是存储强度决定的。这才是学习的真正目标。

问题在于，流利强度高的时候，存储强度未必高。刷完教程觉得全会，第二天就忘一半，这就是流利骗了你。teach 的应对是「合意困难」：设计课程时故意制造一点恰到好处的困难，让提取变费力，费力才能加深存储。

三个工具。提取练习：不看资料，先凭记忆回想，回想不出来再看。间隔：把练习分散到不同时间，而不是一次练完。交错：把相关但不同的主题混在一起练，这个只用于技能练习。

测验设计还有个细节：每个答案的字数要完全一致。因为如果正确答案比错误答案长，用户会通过格式猜答案，测验就失效了。这种细节，说明 teach 是认真把学习科学用在课程设计上的。

## 难度刚刚好

每节课，用户都应该感觉到被挑战得「刚好够」。

太难，挫败，学不下去。太简单，无聊，学不到东西。刚好够，才是学习发生的区间，这就是最近发展区。

teach 怎么确定这个区间？读 learning-records。记录里写了你上次学到哪、卡在哪、后续计划是什么，它据此判断这次教什么。所以学习记录不是写给自己看的存档，是教学系统判断下一步的依据。写记录时留一节「下一步学什么」，AI 就能据此接着教。

如果你没有指定想学什么，teach 就按最近发展区自己判断：读记录、对照使命、教最相关且难度合适的东西。

## 课程和参考文档的分工

teach 有个很清醒的设定：课程很少被重访，参考文档会被一直重访。

所以课程要短、要快、要好看，一次教一个能带走的小胜利。参考文档要做成压缩精华，随时查阅。拿编程学习举例，课程是给学习者一次性读完的，语法速查和术语表是反复回来查的。

术语表在这套分工里地位特殊。一旦建起来，每节课都必须遵守，不能这节课叫 A、下节课叫 B。新增术语要持续维护，就是要避免同一个概念在不同课里长出不同名字。

## 使命会变

学得越多，使命可能越变。这是正常的。

比如你原本想学 Python 是为了写脚本，学到中期发现你真正想要的是做数据分析，使命就变了。

teach 的处理是：更新 MISSION.md，加一份学习记录记下这次变化，而且改使命之前要跟你确认。使命是教学的地基，地基动了，课程方向都要跟着动，不能偷偷改。

## 手把手，开始第一课

走一遍实际流程。假设你想学 Spring Boot 单元测试。

第一步，输入一行。

```
/teach
```

AI 会问你想学什么。你回答：我想学 Spring Boot 单元测试。

第二步，AI 检查工作区。它发现 MISSION.md 是空的，于是先不急着讲课，问你：为什么想学单元测试？

你答：因为项目里测试老写不对，想学会怎么用 tdd 的思路写单元测试，让 AI 帮我写的时候我也能看懂。

使命清楚了，AI 把它写进 MISSION.md。注意，它问的不是「你想学什么细节」，而是「为什么学」，因为只有知道为什么，它才知道每节课讲什么、讲到什么深度、下一步教什么。

第三步，AI 填 RESOURCES.md。它先去找高质量资源：Spring 官方测试文档、JUnit 5 官方文档、权威教程。它不靠自己的记忆讲课，先找好资源打底。

第四步，出第一课。这一课只讲一件事，比如「JUnit 5 的断言怎么写」，短到你 10 分钟能看完，看完有一个能带走的小胜利：写出一条正确的断言。课上推荐一个一手来源让你去读，末尾提醒你：有不懂的随时问，你的老师是 AI。

第五步，学习记录。这节课你卡在哪、学会了什么、下一课该教什么，写进 learning-records/0001。下一节课，它读这份记录，确定还在你的最近发展区内，继续教。

整个流程走完，你得到的不只是一节课，是一套会持续生长的学习系统。每次会话结束，状态都在目录里，下次接着学。

这个例子里的流程是真实的 teach 工作流，课程内容本身是示例。使命、资源、课程、记录四样东西各就各位，学习就不再是一锤子买卖。

## 边界和误区

第一，teach 不是问答。它是跨会话工程。你问一句它答一句，那是普通聊天。你想让它持续教、记进度、算下一步，才用 teach。用一次就跑，它的价值体现不出来。

第二，格式可以改。teach 官方设定课程是自包含 HTML，因为要渲染得漂亮、方便本地打开。但如果你要把课程发到公众号，Markdown 源稿反而是发布流水线的输入，改成 Markdown 完全没问题。改编是 Matt 明确鼓励的，他的 README 里写着 hack around with them，make them your own。工具是工具，不是信仰。

第三，知识靠资源，不靠 AI 记忆。RESOURCES.md 没填好之前，AI 讲的内容都要打问号。这是 teach 最反直觉也最重要的一条规矩。你以为 AI 在教你，其实它在背课文，背错了你也不知道。先让它找好资源，再让它讲课。

第四，智慧不属于 AI。涉及真实世界的判断、品味、实践经验的问答，teach 最终会把你引向社区。别指望 AI 替代真实互动，它自己也这么认为。

## 快速回顾

- 定位： teach 是 productivity 桶正式技能，跨会话有状态教学，user-invoked，输入 `/teach` 开始
- 工作区七件套： MISSION（为什么学）、RESOURCES（资源清单）、NOTES（偏好）、lessons（课程）、reference（速查）、learning-records（进度）、assets（复用组件）
- 三样东西： Knowledge 靠资源、Skills 靠交互课程、Wisdom 靠社区，AI 教不了智慧
- 流利 vs 存储： 流利是幻觉，存储是目标；合意困难三工具：提取练习、间隔、交错
- 最近发展区： 挑战刚好够，读 learning-records 判断下一步教什么
- 课程 vs 参考： 课程很少重访，参考文档经常重访；术语表一锤定音，每课遵守
- 使命会变： 更新 MISSION.md + 学习记录，改前跟你确认
- 硬规矩： RESOURCES.md 填好前绝不信任参数化知识
- 可改编： 课程格式可改（如 HTML 换 Markdown 发公众号），工具不是信仰
