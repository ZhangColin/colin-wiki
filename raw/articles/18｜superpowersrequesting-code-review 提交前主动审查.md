## 场景：求人审查，先把自己这关过了

那阵子我写代码有个毛病：写完就提交，提交就找老王"帮我看看"。

老王看了两回，不干了：

「老谭，你甩给我的都是些什么？ `git diff` 里一半代码我都不懂为啥要改，测试还没跑就丢给我，让我审啥？」

他说得对。 **代码审查不是"别人替你把关"，而是"你把自己的活干到最好，然后请别人帮你看看还有没有漏"。** 前置工作没做好，就是在浪费审查者的时间，也是在浪费自己改 bug 的时间。

`requesting-code-review` （主动求审）讲的就是： **提交审查之前，自己先把该做的做完。** 它是一套"提交前自检"，不是"求人前心虚"。

## 技能是什么：请求审查 = 交一份"能审的活"

`requesting-code-review` 的核心是转换视角： **你要交出去的，不是"我的代码"，而是"一份别人能高效审查的变更"。**

它的准备动作有四步：

1. 自看差异： `git diff` 摊开，自己能讲明白每一行为什么改；
2. 自跑测试： 测试全绿，才有资格谈审查；
3. 自查清单： 命名、边界、遗留 TODO、无用代码，先过一遍；
4. 自写说明： 这个变更做了什么、为什么、想请审什么。

做完这四步再去请求审查，审查者才有东西可审——而不是帮你收烂摊子。

## 怎么用：一次"能审的活"是怎么准备的

以"预算页加超支提醒"这个变更为例，走一遍请求审查前的准备。

### 第一步：先看自己的 diff

请求审查前，先 `git diff` 看一遍自己改了什么：

```
git diff --stat                     # 改了哪些文件，改了多少行
git diff                            # 逐行看差异
```

我自己看的时候发现一个问题：一个变量叫 `amnt` ，图省事缩写的。 **命名是给下一任读者看的，缩写就是给自己埋坑。** 改回 `amount` 。

这一步的价值： **把"我大概改了啥"变成"我清清楚楚改了每一行"** 。自己都讲不清的 diff，别交出去。

### 第二步：跑测试，拿到绿

`requesting-code-review` 的一条铁律： **测试不绿，别求审。**

```
"$MAVEN_HOME/bin/mvn" test
```

全绿。拿到的是一张"这张票子能上桌"的证明。

### 第三步：过一遍自查清单

我给自己定了一张提交前清单，每次请求审查前打一遍勾：

- ☐命名清楚？（ `amnt`
	→ `amount` 这种缩写，消灭掉）
- ☐有遗留 TODO / 注释掉的死代码吗？
- ☐边界条件处理了吗？（空数据、空值、超预算==预算）
- ☐有没有夹带和本次无关的改动？（改了 A 功能，顺带动了 B 文件，要拆出来）
- ☐金额走 `BigDecimal`
	了吗？ `compareTo` 而不是 `equals` 吗？

这步主要是 **消灭低级问题** ，让审查者把精力花在"真问题"上。

### 第四步：写审查说明，请人看"你该看的那几处"

最后，不只是丢一个 diff，而是写清楚"这是什么 + 我改了啥 + 重点想请你审哪"：

```
变更：预算页超支提醒
改了什么：
  前端 Budgets.vue 渲染 spent 字段，spent > limitAmount 标红；
  后端预算接口补充 spent（本月已花）。
重点想请你审：
  1. spent 的聚合逻辑对不对（尤其跨分类、空分类的情况）；
  2. 前后端字段名契约是否一致。
已自检：mvn test / npm test 全绿。
```

**"想请你审哪"这步最关键** ——它把审查者的注意力引导到你心里没底的几处，比"你随便看看"高效十倍。

## 注意事项

1. 测试是求审的敲门砖。 测试不绿就求审，等于没敲门直接闯。
2. diff 里不该有的东西，自己先清掉。 无关改动、死代码、缩写命名，都是审查者眼中的噪音。
3. 写清"想请你审哪"。笼统地"帮忙看看"，审查者不知道从哪看起；点出重点，审查才有效率。
4. 求审的心态是"请帮我找问题"，不是"请夸我"。 准备工作做足，是为了让审查者能专注找真问题，而不是替你擦屁股。

## 本文小结

`requesting-code-review` 把"请求审查"变成一套准备流程：自看 diff → 自跑测试 → 自查清单 → 自写说明。 **你交出去的是一份"能审的活"，审查者才有东西可审。**

那次我把准备做足的变更发给老王，他看了十分钟，回了一句：「这回像样了。我审到两处，你过来看。」

「行。」我抓起外套，「审出问题来，才是这活最大的价值。」

「那你可别上头。」老王笑，「有人给你挑毛病，你要顶回去可就坏了。」
