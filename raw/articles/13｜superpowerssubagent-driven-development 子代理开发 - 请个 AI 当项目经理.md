老王把椅子往前挪了挪：「一次派两个还行。那能不能更进一步—— **一个 AI 当项目经理，把一整个功能从头到尾拆任务、派活、验收？** 」

## 场景：手工派活，还是让 AI 自己转流水线？

前面几篇，拆任务、写计划、派活、验收，都是 **我在主会话里手动协调** 的。活儿一多，我的"协调开销"就上来了。

superpowers 的协作类里最重的一张牌，叫 `subagent-driven-development` （子代理驱动开发）： **主会话当项目经理，读计划、派子代理、做两级审查** ，把"从计划到实现"的流水线交给 AI 自己转。

它跟 `dispatching-parallel-agents` 的分工：

- dispatching-parallel-agents： 我拆好任务，派几个 AI 并行；
- subagent-driven-development： **整个功能我委托出去** ，AI 自己拆、自己派、自己审，我只做指挥和验收。

老王眼睛亮了：「这不等于是……招了个项目经理？」

「是，而且它不用发工资。」我笑，「但它能不能把活干好，取决于你给它喂的计划喂得够不够好。」

## 技能是什么：项目经理 AI 的流水线

`subagent-driven-development` 的运转模型，是 **主会话 + 子代理** 两层：

```
主会话（项目经理）
   ├─ 读计划：把计划文档吃进去，搞清目标、任务、验收
   ├─ 派发：把计划拆成子任务，派给子代理（一次一个或并行）
   ├─ 两级审查：
   │    第一级：子代理自审（它自己检查自己的代码）
   │    第二级：主会话复审（项目经理对照计划验收）
   └─ 循环：不达标 → 打回重做；达标 → 合入
        └─ 子代理（执行者）
              ├─ 读任务：只领自己的那一个任务
              ├─ 实现：写代码 + 写测试
              └─ 自审：跑测试、自查，交回给主会话
```

关键在 **两级审查** ：子代理不能"写完就说完成"，它要自审；主会话也不能"看它说完成就信"，要对照计划复审。两级都过了，才算一个子任务完成。

## 怎么用：让 AI 项目经理跑通"超支提醒全栈"

### 第一步：给项目经理喂一份好计划

项目经理再能干，也得有图纸。我把 `writing-plans` 出的计划（阶段、任务、验收）喂给它，明确这次的范围：

> 实现"预算超支提醒"全栈：后端预算接口带已花金额，前端预算页标红 + 提示。验收见计划。你负责拆任务、派子代理、审查合并。

计划里每步都带验收——这是项目经理拆任务、审结果的尺子。

### 第二步：项目经理拆任务、派子代理

项目经理拿到计划，自己拆出两个子任务，派给两个子代理（各用各的 worktree）：

- 子代理 A： 后端 `LedgerAppService` 加"某分类本月已花"计算，预算接口带上 `spent` ；验收： `mvn test` 全绿。
- 子代理 B： 前端 `Budgets.vue` 渲染 `spent` 、超支标红、弹提示；验收： `npm run build` 过、页面可见。

它派发时的任务单，跟上一篇我们手工写的一模一样—— **文件边界 + 验收标准** 。区别是：这次是 AI 拆的、AI 派的。

### 第三步：两级审查

子代理 A 交回，说"做完了"。项目经理不会直接信——先让它 **自审** ：

> 子代理 A 自审：跑 `mvn test` ，贴出结果；对照任务验收逐条自查，有没有漏？

自审过了，项目经理再 **复审** ——它自己读代码、对照计划：

> 项目经理复审：读 A 的改动，确认接口真的带了 `spent` 、字段名跟前端契约一致、没有夹带私货。

复审发现问题（比如 A 把字段名起成了 `spentAmount` ，跟契约的 `spent` 不一致），项目经理打回去：

> A 的字段名与契约不符（应为 `spent` ）。打回修正后重审。

子代理 A 改完，再走一轮"自审 + 复审"。 **直到两级都绿，才放它过。**

### 第四步：项目经理合并 + 主干验证

两个子任务都过了，项目经理合回主干，再跑一遍完整测试收工：

```
git merge agent-a-budget-spent
git merge agent-b-budget-ui
"$MAVEN_HOME/bin/mvn" test
```

这次，我全程只说了三句话：喂计划、说范围、最后点头验收。 **中间的拆、派、审、合，全是项目经理 AI 干的。**

## 什么时候值得上项目经理

`subagent-driven-development` 是重武器，别什么都用它：

- 任务大、步骤多、横跨前后端 → 值得，比如这次的全栈功能；
- 每个子任务都能独立验证 → 适合，项目经理好验收；
- 就一个文件 20 行代码 → 杀鸡用牛刀，直接自己写。

判断标准： **这个活，拆分和审查的收益，盖过派发的开销吗？** 盖过，上。

## 注意事项

1. 喂给项目经理的计划必须带验收。 项目经理拆任务、审结果，全靠计划里的验收标准。计划写不明白，项目经理就审不明白。
2. 两级审查一步都不能省。 只信子代理自审，等于让选手自己给自己打分；只信项目经理复审，子代理的细节问题又容易被漏。两层是互补。
3. 打回要说清理由。 "不行"三个字没用，要指出哪不符契约、哪没过验收。理由清楚，子代理才改得动。
4. 项目经理也在你的上下文里干活。 它拆的任务越多，上下文越挤。一次别让它吞整个大项目，分批来。
